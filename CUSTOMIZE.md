# Customizing your forum

Everything brand-related lives in **`forum/web/site.config.js`** — deploys
never overwrite it. Runtime wiring (`forum/web/config.js`) is regenerated by
`deploy.sh`; don't hand-edit that one.

## site.config.js reference

```js
window.SITE_CONFIG = {
  name: "My Community Forum",        // site name: browser title, landing hero, footer fallback
  tagline: "A place to meet…",       // landing-page intro (admins can override via Admin → Site Pages)
  logo: "assets/logo.svg",           // path under forum/web/ — swap in your own file
  footer: "My Community Forum · …",  // footer line on every page
  layout: "sidebar",                 // "sidebar" | "topnav"  (see Layouts)
  theme: "neutral-light",            // file name in forum/web/themes/  (see Themes)
  nav: [                             // the site navigation, in order
    { label: "Home",   href: "#/" },
    { label: "Forum",  href: "#/forum" },
    // …any built-in route: #/about #/contact #/photos #/members #/links
    { label: "Events", href: "#/category/events" },  // deep-link into a category
  ],
};
```

An **Admin** nav item is appended automatically and shown only to logged-in
admins. Built-in routes not in your nav still work by URL — removing a nav
item hides it, it doesn't disable the page.

## Layouts

- **`sidebar`** — classic two-column: colored nav column on the left, content
  on the right. Collapses to a top bar under 720px.
- **`topnav`** — modern horizontal header (logo, nav, login button), content
  full-width below.

Both are pure CSS over the same markup; switch anytime by editing the config
and re-deploying (or just re-uploading `site.config.js`).

## Themes

Bundled: `neutral-light` (default), `dark`, `warm-classic` (parchment + olive,
serif headings), `cool-modern` (white + teal).

A theme is one CSS file in `forum/web/themes/` that defines only CSS custom
properties. To make your own, copy an existing file and define **the full
contract** (structural CSS uses only these):

```
--bg --card --ink --muted --accent --accent2 --line --rowalt --head --danger
--frame-bg --nav-bg --nav-border --nav-ink --nav-active-bg --nav-active-ink
--pill-bg --pill-ink --hero-bg --hero-border --hl --ok
--err-bg --err-border --err-ink --footer-ink --btn-ink --shadow
--display --font
```

Colors must be 6-digit hex (`#rrggbb`) — the login-page branding script parses
them. The one exception is `--shadow`, an `rgba()` value because it needs
alpha. `--display` (headings) and `--font` (body) are font stacks.

A theme name that doesn't resolve falls back to `neutral-light` and logs a
console error, rather than rendering the site with no colors at all.

## Logo

Replace `forum/web/assets/logo.svg`, or add your own file under
`forum/web/assets/` and point `logo:` at it. The path is relative to
`forum/web/` (so `assets/my-logo.png`). Keep logos inside `assets/` — that's
the directory the deploy uploads with a long cache header. Any web format works
in the site itself; the Cognito login page needs it convertible to PNG
(SVG/PNG/JPG all fine).

## Login page branding

The Cognito-hosted login page (used for social sign-in; email login is
in-page) can be themed to match the site:

```bash
cd forum && bash scripts/apply_login_branding.sh
```

It reads your active theme's colors and configured logo. Not managed by
CloudFormation — re-run it after a fresh stack create or when you change
theme/logo. Uses macOS `sips` for image conversion.

## Page content (no code)

Logged in as an admin: **Admin → Site Pages** edits the About, Contact, and
home-intro text; **Admin → Links** edits the links list; announcements and
photo albums are managed from the same admin area.

## Privacy page

`forum/web/privacy.html` is a static page linked from the footer. It picks up
your site name automatically, but read it once and adjust the wording (age
requirements, contact email) for your community.
