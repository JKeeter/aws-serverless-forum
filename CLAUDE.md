# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A **white-label serverless forum template**: a complete community-forum
website anyone deploys to their own AWS account (S3 + CloudFront + HTTP API +
one Lambda + DynamoDB single-table + Cognito). Static no-build SPA front end,
~$0–2/month at small scale, no server to patch. This repo is the template —
users clone it, edit `forum/web/site.config.js`, and run the deploy script.

## Commands

```bash
cd forum
npm install                     # test deps (dynalite, playwright)
node test/itest.mjs             # 93 API checks — real Lambda handler vs local DynamoDB; no AWS, no Docker
node test/web_smoke.mjs         # 32 browser checks — structure, XSS-safety, config chrome, themes, layouts
npx playwright install chromium # once, before web_smoke/devserver
node test/devserver.mjs         # local forum at http://localhost:8100 (dev-token login printed at startup)
bash scripts/deploy.sh          # deploy to AWS (us-east-1); env contract in DEPLOY.md
sam validate --lint             # template check
```

## Load-bearing invariants (do not relitigate)

- **Stored-XSS defense**: user text is stored as text and rendered with
  `textContent`/DOM nodes — **never `innerHTML`**. Media renders only from
  same-origin `/media/` paths. This is the template's core security promise.
- **Route lockstep**: the `routeKey` strings in `src/api/index.mjs` must match
  `template.yaml`'s routes exactly (itest checks this) — 30 routes.
- **No build step** for `web/` — plain HTML/CSS/JS uploaded as-is.
- **Config split**: `web/config.js` = runtime wiring, REGENERATED by deploy.sh
  (`window.FORUM_CONFIG`); `web/site.config.js` = user branding, never touched
  by deploys (`window.SITE_CONFIG`: name/tagline/logo/footer/layout/theme/nav).
- **Themes** are CSS-variable-only files in `web/themes/` (contract listed in
  CUSTOMIZE.md); structural CSS lives in `web/styles.css` and may not hardcode
  colors (lightbox overlay whites are the one allowed exception). Layouts are
  body classes `layout-sidebar` / `layout-topnav` — CSS only, same markup.
- Deploy region must be **us-east-1** (CloudFront's ACM cert lives there).

## Architecture pointers

- `docs/ARCHITECTURE.md` — full design: single-table key shapes (CAT/TOPIC/
  POST/USER/ANNOUNCE/ALBUM/PAGE), auth model, security posture, costs.
- `src/api/index.mjs` — the entire API in one Node 20 Lambda.
- `IMPORT.md` — legacy-forum import: `topics.json` schema → `build_seed.py` →
  `load_seed.py`; imported topics are `archived:true` read-only.
- `CUSTOMIZE.md` — site.config.js reference, themes, layouts.

## Gotchas

- The Node 20 Lambda runtime bundles AWS SDK v3, so `src/api` ships no
  `node_modules`; tests install the SDK at the `forum/` root.
- `src/api/index.mjs` reads `DDB_ENDPOINT` (unset in prod) only so tests can
  point at dynalite. Leave it unset in AWS.
- `deploy.sh`, `load_seed.py`, `load_gallery.py` are idempotent —
  deterministic keys mean re-runs overwrite, never duplicate.
- **Cognito callback URLs are registered post-deploy** by
  `scripts/register_callback.py` — they can't live in the template
  (Client → Distribution → HttpApi → Client circular dependency).
- **Cognito Managed Login branding is NOT in CloudFormation** — re-run
  `scripts/apply_login_branding.sh` (theme-derived; macOS `sips`) after a
  fresh stack create or theme change.
- Web tests + dev server need Playwright's Chromium (`npx playwright install
  chromium` once).
- Auth is embedded in-page (Cognito API: `USER_PASSWORD_AUTH`, sign-up,
  forgot-password). The Hosted UI is used only for social-IdP redirects.
